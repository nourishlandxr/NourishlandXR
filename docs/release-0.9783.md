# Totem motion and hero autoplay · V0.9783

## Repair

The first Creator selection created and rendered a WebGL portrait on the browser's main thread. The live diagnostic recorded a 1,047 ms long task immediately after the click, blocking the transition's first frames. Preparing the same shared XR sculptures once removes that work from navigation. Three 640 × 960 WebP portraits total 94,914 bytes, including the same painted names, measured sign targets and ground anchors. Regenerate them with `node root-site/tools/render-totem-portraits.mjs` while the local preview is running.

The navigation waits for a decoded portrait before starting its 960 ms transition. Stale branch requests are discarded, repeated ResizeObserver notifications no longer cancel movement, and the existing living ground connection and smaller labelled ancestor remain.

The hero now requests muted inline autoplay immediately and explicitly sets the autoplay attribute. Poster decoding does not gate the video request. Pause and replay/reset buttons have been removed. Menu, route and tab pauses resume automatically; reduced-motion continues to show the sharp poster. The video files, their quality and the known baked-in food crevice are unchanged.

## Validation and boundary

The release browser checks sample actual intermediate transforms and first-frame delays, reverse the journey and switch branches during movement. They also check desktop/phone autoplay, no controls, menu pause/resume, missing-poster playback, reduced-motion, the original wheel, three places, Field preview and discovery die. Browser viewport checks do not establish physical phone/headset acceptance.

V0.9783 is a 39-file additive frontend overlay over V0.9782. CSS imports, including `url(...)` syntax, and JavaScript module imports receive release query versions. Every previous production hash is recorded and checked by the protected publisher before writes. No routing, WordPress, API or project data changes are included.
