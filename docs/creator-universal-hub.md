# Universal Creator hub

Local web milestone V0.9757. The web Creator entry defaults to a shared project hub in Desktop, Field and Spatial access. This is source implementation; deployment and physical device acceptance are separate.

Creator has a game-style interface throughout: the supplied ceramic Nourishland logo, six large launch buttons, raised mineral surfaces, compact access controls and keyboard/aim focus labels. Loading uses the real authentication/project request lifecycle, with animated logo rings and no artificial timer or progress percentage. Reduced-motion preferences disable the animation. The original logo artwork is preserved; its emblem is cropped in CSS for the circular display. Records, knowledge, maps, paths, field capture, spatial preparation, guided setup and project settings share the forest shell around light editing surfaces. Direct PIMO URLs load the same style stack; project canvases retain the six tool destinations and local-storage notice. The in-session WebXR hub and object list use the same dark control surfaces.

Every detailed project tool has the same six navigation destinations and a visible current-tool state. Sub-navigation in the record workbench only exposes tasks relevant to the current tool. Route updates preserve the selected Site and record in the tool links, including after changing selection. Phone navigation scrolls within its own rail; the record inspector appears before the register on narrow screens. Common close/back/pagination actions use compact named icon controls. Existing save/discard guards still apply to cross-tool navigation.

The same six groups appear everywhere: Areas & objects; PIMOs & content; Discovery Paths; Map; Preview; Project details. Existing project, Site and record identities are retained. The responsive record/knowledge editor, tour authoring service and PIMO canvas are reused rather than copied into phone or headset implementations.

Phone browsers use the visual PIMO editor with touch input. Camera availability and navigator.xr do not enable spatial PIMO authoring. The phone gate applies to the menu, direct XR URL and programmatic editor entry. Headset browsers can open the existing spatial PIMO canvas; actual immersive session support and user permission are checked when starting XR. Desktop can use its 3D preview.

PIMO canvases still save in browser storage with JSON transfer. The hub retains the return project context but does not pretend these graphs are attached to live project records. Project knowledge editing uses the existing record APIs.

Discovery Paths mounts the same tour studio on all screen sizes. It saves draft tours with existing reference and publication checks. Hunt/Quiz correct-answer gates and discovery unlock rules remain planned. Native Unity Guides and web tours are not silently converted or synchronized by this navigation change.

The WebXR wrist/menu hub is now a transparent world-locked Creator panel. The six groups open submenus without ending XR: object placement and inspection, existing plant knowledge/PIMO workspaces, shared Discovery Path authoring and inline preview, area/line mapping, scene inspection and project/device tools. Paths reuse the same tour API and editor with an XR presentation and existing save/conflict rules. Unsaved edits block menu changes and closing. Uploads, project setup/publication and the standalone PIMO graph canvas remain explicit screen-editor handoffs with confirmation; they are not presented as in-session features. Incomplete mapping or placement must finish or cancel before a tool handoff.

The XR panel uses the existing DOM-to-WebGL mirror with an alpha-preserving texture, opaque text over adjustable glass, world locking, recenter, ray focus feedback, a responsive virtual keyboard, visible paged dropdowns and an inner scroll region that leaves the header/close controls available. It is not a new native Unity implementation. The current native plant workspace is distinct from the standalone spatial graph editor.

The shared hub and existing editors protect unsaved changes before navigation. Field observations continue to use their own queue and offline behavior. No new shared database, login bypass or automatic publication is introduced.

Validation: tests/creator-hub.test.mjs covers device capabilities and route identity. artifacts/creator-workbench-browser-qa.mjs checks desktop, phone and headset-browser menus, phone spatial suppression, record save, draft path save/reopen, dirty navigation, selected record links, settings and creation, empty projects, 13 phone routes, 320/390/768px record layouts, world-locked menu callbacks and the welcome version. It also checks loading/reduced motion, keyboard controls and title contrast. artifacts/creator-workbench-maps-qa.mjs checks flat/3D maps and spatial preparation on desktop and phone widths. Browser fixtures do not establish physical Quest, Android camera or XR tracking acceptance.

Access and wrist contract (V0.9757): Android phones remain touch-first and create neither wrist surfaces nor the Creator XR panel, even when navigator.xr or a camera is available. Direct standalone PIMO XR entry also checks this gate. Spatial Creator devices use two independent wrist menus: left is general settings, standard-controller/hand/automatic input choice, Creator hub, panel recenter and exit; right is the current placement, mapping draft, selected object, plant knowledge editor or path draft. The right wrist offers Save/Preview/Discard for a path and Apply/Cancel for a knowledge edit. The standalone PIMO XR canvas has equivalent left-general and right-cell/text-edit wrist panels. Each wrist is mounted to its matching tracked hand or controller; the opposite hand operates it. No wrist panels appear in desktop 3D preview. Tutorial and Demo use their existing default wrist configuration.

The same phone restriction applies after entering camera AR. The general Control Panel stays in the touch overlay with screen settings and tap instructions. It is not attached to the WebGL panel renderer or XR controller events; world-space interaction reports and attached controllers do not promote a phone to headset mode. Plant and place markers remain part of the camera experience.

Current XR validation artifacts: creator-xr-browser-qa.mjs and creator-xr-fixture.html exercise the real alpha texture and a two-eye Three.js scene, world locking/recenter, ray focus, opacity, keyboard/dropdown editing, path draft persistence/inline preview, explicit screen handoff and Android suppression. runtime-wrist-menu.test.mjs covers independent left/right shortcuts, contextual updates, phone suppression, opposite-hand ownership and mirrored controller offsets. This does not establish physical headset tracking, comfort or performance.
